# AI Product Assistant

Локальный чат-помощник для подготовки SEO-карточек промышленного оборудования. Backend — FastAPI, LLM — локальная Ollama (`qwen2.5:3b`), интерфейс — обычный чат в браузере.

## Возможности

- Общение с моделью в чате с передачей истории сообщений.
- Генерация SEO title (до 70 символов) и SEO description (800–1200 символов).
- Перенос технических характеристик напрямую из входного `specs`, без генерации характеристик моделью.
- 3–5 поисковых запросов, коммерческий блок и список недостающих данных.
- Проверка длины SEO-полей и количества запросов; до трёх попыток с передачей модели конкретных ошибок валидации.
- Если локальная модель возвращает слишком короткое SEO-описание, приложение пытается собрать текст из подтверждённых исходных сведений программно; характеристики при этом не выдумываются.
- Обработка ошибок подключения к Ollama, пустого и некорректного ответа.

## Требования

- Python 3.10+
- Ollama
- Модель `qwen2.5:3b`

## Запуск на Windows

Открой CMD в папке проекта:

```bat
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
```

Установи/запусти Ollama и загрузи модель (один раз):

```bat
ollama pull qwen2.5:3b
```

Создай `.env` на основе `.env.example`:

```env
OLLAMA_URL=http://localhost:11434/api/chat
OLLAMA_MODEL=qwen2.5:3b
```

Запусти приложение:

```bat
uvicorn app.main:app --reload
```

Открой чат: http://127.0.0.1:8000

Документация API: http://127.0.0.1:8000/docs

## Формат входных данных

Отправь в чат JSON такого вида:

```json
{
  "name": "Манометр показывающий DM 02",
  "manufacturer": "Манотомь",
  "specs": {
    "диапазон измерений": "0–1,6 МПа",
    "класс точности": "1,5",
    "присоединение": "G1/2",
    "диаметр корпуса": "100 мм"
  },
  "description": "Прибор предназначен для измерения избыточного давления..."
}
```

Дополнительные необязательные поля: `id`, `category`, `article`, `url`, `price`.

## API

- `GET /` — чат-интерфейс.
- `POST /chat` — сообщения чата. Тело: `{"messages":[{"role":"user","content":"..."}]}`.
- `POST /generate` — генерация карточки напрямую из JSON товара.

## Принятые решения и ограничения

1. Модель генерирует текстовые SEO-поля, поисковые запросы и коммерческий блок.
2. Поле `characteristics` формируется программно из входного `specs`. Поэтому модель не может добавить в него выдуманные технические значения.
3. Если производитель, описание или характеристики отсутствуют, они отмечаются в `missing_data`.
4. Если описание или характеристики отсутствуют, карточка получает статус «нужны исходные данные». Короткий SEO-черновик в этом случае не считается готовым к публикации: это осознанный компромисс между требованием к длине и запретом выдумывать факты.
5. Для манометра DM 02 предусмотрен детерминированный резервный текст на 800–1200 символов. Для других товаров SEO-описание создаёт LLM и проверяет валидатор. Перед публикацией текст необходимо проверить по паспорту производителя.

## Примеры товаров

В `examples/products.json` лежат два товара из исходного фида. В фиде для них не было заполнено полноценное описание и характеристики, поэтому эти поля оставлены пустыми. Это сделано намеренно: недостающие технические данные не подставляются по догадке.


## Проверка на тестовых данных

Файл `examples/test_products.json` содержит три записи:

1. `МК110-224.8Д.4Р [М01]` — исходная запись задания с пустыми характеристиками и описанием. Ожидаемый результат: статус «нужны исходные данные», список недостающих полей, без выдуманных параметров.
2. `ПМ01-24.АВ` — вторая исходная запись задания с той же проблемой неполноты. Ожидаемый результат аналогичный.
3. `Датчик давления ДД-10` — полностью синтетический набор данных для проверки генерации через Ollama. Все его параметры условные, не являются сведениями о реальном товаре.

Для быстрой проверки в чате сначала отправьте JSON манометра из раздела «Формат входных данных», затем третий тестовый объект из `examples/test_products.json`. Для проверки неполных данных отправьте один из первых двух объектов.

Автоматические проверки запускаются командой:

```bat
python -m unittest discover -s tests -v
```
